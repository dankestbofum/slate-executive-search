# Manager pilot walkthrough — September 22, 2026

## Result

A new manager can complete account setup, create a workspace, and open a synthetic search. With per-project billing in local test mode, the new search immediately lands on **Project payment** and has `unpaid` access. The payment gate rejects a candidate write with HTTP 402. The hosted pilot cannot yet complete the requested paid buyer-to-closeout journey: the live public offer reports billing mode `off`, no configured price or allowance, and no checkout. In that mode, new hosted searches receive legacy access and may proceed without payment. This is a deployment/owner-decision blocker, not evidence that the local payment gate failed.

The downstream search workflow was exercised in the existing isolated browser fixture with *legacy* access: candidate receipt, independent sealed scoring, score release, and a connected semifinalist-to-closeout/export/archive path passed in Chromium. It does not establish that a newly **paid** project can make that transition.

## Scope and limits

No production record was changed, no real person was invited or messaged, no checkout or paid AI call was made, and nothing was deployed. Clerk's SDK/UI is stubbed while the local server verifies signed fixture tokens. Billing is off for the downstream legacy-flow tests; the new-manager test uses test mode with no offer/provider. Research HTTP responses are mocked in browser tests. The baseline ran on Node 22.18.0, below the repository's Node 24 floor. Candidate mail is `echo` and the browser fixture permits uploads with an accept-all scanner, unlike the reported hosted configuration. Real Clerk, Stripe, Anthropic, and production recovery still require a hosted rehearsal.
